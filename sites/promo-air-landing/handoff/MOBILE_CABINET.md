# Мобильный кабинет: iOS и Android

16.10.2026. Design by Promo.Art. Открыть /cabinet/ на телефоне. Все 10 разделов используют те же данные и сценарии, что desktop. Это адаптивный веб-интерфейс, не IPA/APK и не опубликованное приложение.

## Реализовано
На ширине до 700px: нижние вкладки Главная / Заведения / Музыка / Расписание / Ещё. Остальные разделы открываются через выдвижное меню. Сохранены прямые ссылки и back/forward. Нижний плеер раскрывает перемотку, предыдущую/следующую подборку, избранное и управление громкостью. На iOS системная громкость может определяться ОС, slider следует заменить подсказкой/системным контролом в нативной оболочке после проверки реальных устройств.

Safe-area сверху/снизу и по краям, viewport-fit=cover, поля 16px для предотвращения автоматического zoom Safari, touch targets от 44px, гибкое расписание, горизонтальные фильтры, одно­колоночные тарифы, диалоги как bottom sheet с прокруткой. При обнаружении экранной клавиатуры нижние панели скрываются, чтобы не перекрывать ввод. Есть reduced-motion, focus и ограничение Tab внутри открытого мобильного меню. CSS mobile.css дополняет cabinet.css; mobile.js использует существующие data-page и один HTMLAudio.

## Для Codex
Интегрировать один responsive кабинет, не создавать отдельную БД/авторизацию для мобильной версии. Мобильный /app/ оставить визуальным референсом для приложения, бизнес-логику и player state переиспользовать из кабинета. Не загружать случайные внешние страницы в WebView с привилегированным native bridge.

Если целевой проект уже имеет React Native/Flutter/Capacitor, использовать его стек и существующую схему навигации. Если native проекта нет, этот пакет даёт готовый frontend; оболочку и сборку выполнять отдельным этапом после изучения репозитория. Не называть простую WebView нативной реализацией всех функций.

Для iOS: safe-area и системный back, audio session для реального фонового воспроизведения, interruption/route changes, lock-screen controls, воспроизведение при блокировке только после реализации и проверки. Для Android: edge-to-edge/insets, системный Back, корректный выход из fullscreen player/dialog/menu, MediaSession и foreground playback service для реального фонового звука. В браузерном прототипе эти native функции не реализованы. Системный Back должен сначала закрывать верхнюю панель, затем экран; это требуется при подключении native router.

Auth: действующая сессия платформы; в native OAuth использовать системную авторизацию и безопасные redirect URI, токены в Keychain/Keystore по архитектуре существующего проекта. Не переносить localStorage токены в native как постоянное защищённое хранилище. Разрешения спрашивать только для реально реализованной функции. Push, offline/downloads, Bluetooth/Cast и pairing устройств не входят в текущую реализацию.

## Приёмка на устройствах
- iPhone: Safari, портрет/альбом, вырез/домашний индикатор, открытая клавиатура, zoom текста, динамическая адресная строка.
- Android: Chrome, жестовая и трёхкнопочная навигация, системная клавиатура и Back, узкие/большие экраны.
- 320/360/390/430/768px, длинные названия заведений и объявления; никакой обрезки критичных действий.
- Все разделы доступны через tabs/Ещё; диалог сохраняет/отменяет изменения и прокручивается с клавиатурой.
- Один источник звука, play после жеста, ошибки сети, seek/favorites, отсутствие ложных команд реальному устройству.
- VoiceOver/TalkBack и крупный системный шрифт; подписанные кнопки и понятный порядок фокуса.

Пока выполнены проверки JS-синтаксиса и ссылок. Реальные iOS/Android и визуальная браузерная QA в текущей среде недоступны. Перечень выше является задачей приёмки, не отчётом о пройденных проверках.
