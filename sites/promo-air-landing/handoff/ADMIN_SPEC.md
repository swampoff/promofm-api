# PROMO.AIR: админка для управления заведениями

Дата: 16.10.2026. Статус: интерактивный frontend-прототип. Дизайн: Promo.Art. Маршрут прототипа /admin/, production route определить по действующему router. Все экраны noindex. Прототип опубликован внутри существующего owner-private Site, отдельная production admin auth не реализована.

## Визуальный контракт
Референс references/admin-layout.jpeg. Сохранены левое меню, верхний поиск/профиль, четыре метрики, центральная таблица, правая очередь модерации и быстрые действия, нижние журнал/поддержка/материалы. Вместо фиксированных 142/118/12/12 счётчики вычисляются из десяти демо-заведений. Таблица показывает все записи, без притворной серверной пагинации. При интеграции нужен серверный cursor/pagination.

Персонаж справа снизу заменён отдельным прозрачным ассетом admin-dj.webp. Герой из references/mascot-reference.jpeg: чёрное худи, короткая чёрная причёска, чёрные наушники, коралловые очки, тёплая оранжево-коричневая кожа, DJ-пульт. Изменение касается админки, не заменяет основного лысого Нико во вселенной бренда. Мия остаётся в блоке поддержки с использованием существующего атласа. Макет реализован HTML/CSS, не как фоновая картинка с невидимыми кнопками.

## Состояния и полномочия
Состояния demo: active, pending, attention, offline, blocked, rejected. Это UI-упрощение. В production разделить жизненный цикл модерации, административную блокировку, подписку и технический online/offline. «Офлайн» не равен заблокированному или неоплаченному заведению. Статус «Играет» не доказывается наличием платной подписки.

Использовать существующие роли, не создавать параллельную систему. Минимальная карта для проверки:
- Admin: управление сетью в разрешённом scope.
- Moderator: рассмотрение заявок, причина решения; без финансовых операций.
- Finance: просмотр/выгрузка финансов, возвраты только по отдельному разрешению и процессу.
- Support: просмотр разрешённых карточек, обращения; без назначения себе ролей и скрытого входа под владельцем.
- Owner: только свои организации/заведения; административные API недоступны.

Решение по pending-заявке выполняется один раз. Повтор или изменение другим сотрудником возвращает конфликт с обновлением карточки. Отклонение и блокировка требуют причины. Разблокировка восстанавливает допустимое состояние по серверным правилам, не открывает доступ в обход оплаты/модерации. Назначение плана не равно оплате и не должно само списывать средства.

Для аудита: actor ID, роль, organization/venue IDs, timestamp UTC, тип действия, причина, before/after, correlation/idempotency key. Реальный журнал хранится серверно и не изменяется обычным администратором. Не писать токены, платёжные реквизиты и лишние персональные данные в журнал. Текущий localStorage журнал является только UX-макетом.

## Финансы
DEMO-101…105 вымышлены. Валюта RUB; суммы в JS хранятся целыми копейками. Оплаты, ожидания, возвраты и ошибки считаются отдельно; это не MRR и не чистая выручка. Период в прототипе фиксирован 14–16.10.2026, не «сегодня» и не live-данные. CSV защищает начальные формулы, кавычки и разделители. При подключении сохранить доступность экспорта только уполномоченным ролям и ограничить scope.

Возврат в production выполняется существующим payment backend с серверным контролем суммы/валюты/остатка, защитой от повторов, подтверждением провайдера и состояниями pending/succeeded/failed. Не реализовывать реальный возврат только client-side кнопкой. В прототипе кнопок списания/возврата нет.

## Локальные данные и границы
localStorage key promo-air-admin-demo-v1, version=1; ключ не связан с кабинетом владельца. Модель admin-state.js: seed, validation, filter, status transition, integer totals и CSV escaping. admin.js: templates, routing, dialogs и local persistence. Загружаемые строки экранируются перед HTML. Нет fetch/API, токенов, серверных ролей, billing, доставки сообщений и управления устройствами. Браузерное хранение не является защищённой БД и не переносится в production.

Адаптивность: до 700px боковое меню выдвигается, карточки складываются, таблица доступна горизонтальной прокруткой с клавиатуры, формы 16px и touch targets 44px. Меню с Tab trap, dialogs с native focus handling, reduced-motion. Реальные browser/screen reader проверки ещё необходимы.

## Приёмка
- Все 10 разделов, прямые ссылки, back/forward/reload, поиск/фильтры/empty/error/loading.
- Таблица и карточки совпадают по scope, метрики соответствуют данным.
- Approve/reject одновременно двумя администраторами, отказ без причины, повтор запроса, блокировка и восстановление, тариф без неявной оплаты.
- Сервер запрещает доступ owner/moderator к финансовым и чужим организационным данным независимо от скрытых кнопок.
- Биллинг сверяется с провайдером, экспорт правильной валюты/периода, повторный возврат не создаётся.
- Черновик сообщения не показывается отправленным; фактическая доставка имеет отдельное состояние.
- Desktop 1280/1440/1920, iOS/Android 360/390/430, клавиатура, focus, длинные имена, таблицы, safe-area.
- Сборка целевого проекта, тесты и audit подтверждены до production rollout.

В этой среде: JS syntax, тесты чистой модели и smoke render 10 шаблонов с DOM-заглушкой. Это не визуальная browser QA и не backend-тестирование. Использование поддерживаемого браузера недоступно, поэтому визуальная приёмка остаётся задачей интеграции.
