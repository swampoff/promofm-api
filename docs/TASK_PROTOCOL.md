# Задачи cloud ↔ laptop без курьера — GitHub Issues

С 2026-07-07 задачи между cloud-Claude и laptop-Claude ходят через
GitHub Issues repo `swampoff/promofm-api` (единый трекер на все репо
платформы), а не через пересылку сообщений Никитой. Никита выпадает
из роли курьера, но остаётся владельцем решений.

## Метки

| Метка | Смысл |
|---|---|
| `laptop` | задача лэптопу (прод-SQL, VPS, деплой, runtime-тесты) |
| `cloud` | задача cloud-сессии (код, миграции, FE, доки) |
| `wip` | взята в работу (ставит исполнитель) |
| `decision-needed` | нужен ответ Никиты — исполнители НЕ трогают до его комментария |

## Тело задачи (шаблон)

```
## Контекст
<что и почему; ссылки на HANDOFF §, коммиты>

## Критерий (декларативный — что должно стать правдой)
<один проверяемый сценарий>

## Pre-flight / риски
<таблицы-колонки для \d, что может сломаться>
```

## Цикл

1. Постановщик создаёт issue с меткой `laptop`/`cloud`.
2. Исполнитель: ставит `wip` → работает по CLAUDE.md-протоколу →
   пишет результат КОММЕНТАРИЕМ (декларативно: что стало правдой,
   коммиты) → закрывает issue.
3. Уперся в продуктовое/денежное решение → метка `decision-needed`
   + вопрос ОДНИМ комментарием, issue остаётся открытым.
4. Cloud-сессия при старте проверяет открытые issue с меткой `cloud`
   (см. CLAUDE.md) и комментарии к своим `laptop`-задачам —
   это замена «перескажи, что ответил лэптоп».

## Laptop-сторона: раннер

`scripts/laptop-task-runner.sh` + cron/launchd (раз в 30 мин).
Режимы:
- **default (safe)**: находит новые `laptop`-задачи без `wip` →
  уведомление на macOS + печать команды запуска. Никита/лэптоп
  запускает claude сам.
- **AUTONOMOUS=1**: сам ставит `wip` и запускает `claude -p` с телом
  задачи. ⚠️ Включать ТОЛЬКО осознанно: это машина с SSH к проду.
  `--dangerously-skip-permissions` НЕ использовать — пусть опасные
  команды упираются в permission-правила из настроек claude.

Что НЕ ходит через issues: секреты, PII (bounce-списки и т.п.),
дампы прод-данных. Issues видны всем, у кого есть доступ к репо.
